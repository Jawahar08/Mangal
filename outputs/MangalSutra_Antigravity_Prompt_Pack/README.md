# MangalSutra 2.0 — Antigravity Prompt Pack

A five-folder prompt system for building MangalSutra as a coherent, UX-first relationship platform. The pack keeps the full product vision visible while delivering it in audited, reviewable phases.

## Folders

1. **01_Master_Context** — persistent project context and the complete feature-coverage index.
2. **02_Audit_and_UX** — repository audit, feature gap analysis, journey maps, and UX foundation.
3. **03_Phase_1_Core_Web** — the first responsive web release: account access, onboarding, profiles, discovery, matching, compatibility, messaging, Astra, and basic trust.
4. **04_Phase_2_ChaanBean_Trust** — consent-based, evidence-backed verification and the ChaanBean Trust Vault.
5. **05_Phases_3_to_6_Ecosystem** — separate prompts for marriage intelligence, Second Chapter, Pratha, marketplace, and cross-phase review.

## Recommended use in Antigravity

1. Add both source attachments to the Antigravity project if they are available there.
2. Paste or save 01_Master_Context/00_MASTER_PROMPT.md as the project-wide instruction.
3. Start with 02_Audit_and_UX/01_REPOSITORY_AUDIT_AND_UX_PROMPT.md. Ask Antigravity to inspect the actual repository and return its audit before it makes major changes.
4. Review the audit, then use the UX foundation prompt and Phase 1 prompt. Work in small vertical slices.
5. Use the Phase 2 prompt only after the trust architecture, provider access, consent, privacy, and security requirements are understood.
6. Use the Phase 3, 4, 5, and 6 prompts one at a time, in roadmap order. These describe the long-term ecosystem; they are not a request to build every phase in the first release.
7. Use the cross-phase acceptance prompt after each meaningful phase or release.

The master prompt contains the full product scope and workflow. For best results, also include the complete feature-coverage index and only the phase prompt currently being worked on. The index is the traceability checklist; the phase prompt determines current scope. If the original attachments are unavailable in Antigravity, the master prompt and index preserve their requirements.

## How the source documents are handled

The PDF and pasted specification describe the desired product and also contain workflow instructions for whoever works on the codebase. This pack preserves both, but distinguishes them:

- Product features, design direction, safety rules, and roadmap items are requirements to track.
- The source instruction to inspect the repository before changing it is an execution workflow. It is retained in the audit prompt.
- Long-term features remain in the inventory even when they are out of scope for Phase 1.
- Unverified integrations, proposed database tables, pricing, and future capabilities are plans or hypotheses until verified. Do not represent them as implemented.
- Incidental editorial notes in the source are not product features.

The source specification lists the React, TypeScript, Vite, Supabase/PostgreSQL, Edge Functions, Gemini, Firebase Cloud Messaging, and Capacitor stack as an expected foundation. Prompts explicitly tell Antigravity to confirm the repository's actual stack before relying on it.
