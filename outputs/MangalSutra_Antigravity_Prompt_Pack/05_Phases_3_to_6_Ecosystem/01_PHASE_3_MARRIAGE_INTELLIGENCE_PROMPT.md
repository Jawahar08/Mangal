# PHASE 3 — MARRIAGE INTELLIGENCE PROMPT

Read the Master Prompt, feature index, repository audit, and prior-phase implementation. Build marriage-intelligence features as optional tools for shared understanding, not as diagnoses, verdicts, or predictions.

## Scope

### Relationship compatibility and readiness

For the post-match journey, bring together computed compatibility, each partner's user-approved limited trust statuses, important conversations, and an optional Pratha or couple-wellbeing invitation. Keep private reflections separate and require consent for anything shared.

- Reuse validated astrology inputs and calculated compatibility; keep deterministic rules separate from AI explanations and UI.
- Support the 12 modern dimensions listed in the feature index when a defensible question set and data model exist.
- Present useful categories: Strong, Needs discussion, Important conversation required. Explain missing answers and limitations.
- No arbitrary credit-like score, clinical/scientific diagnosis, or marriage-success prediction. Consequential assessments need a defensible methodology and appropriate expert input.
- Explain that differences are conversation prompts, not evidence that a relationship will fail.

### Talk Before You Marry

Create paced prompts on money/financial independence, parents/family responsibilities, children/parenting, career/relocation, lifestyle/social expectations, religion/festivals, living arrangements, communication, conflict, and future goals. Use couple-specific context only where supported. Let each person reflect privately before choosing to share. Support save, skip, revisit, and completion at their own pace.

### Couple Conversation Mode

Activate only after both partners explicitly agree. Sections: Know Each Other, Money, Family, Home, Children, Spirituality, Intimacy, Mental Wellbeing, Career, Future. Store private answers separately from shared answers. Require explicit sharing controls for each answer or summary; never reveal private reflections silently or use them for unrelated purposes. Allow shared notes and mutual milestones only where appropriate.

### Relationship Risk Signals and Ask MS Trust

- Risk-signal topics may include extreme financial expectations, major child expectation differences, contradictory marital history, inconsistent profile information, lifestyle mismatch, money pressure, unwillingness to discuss key topics, reported controlling behavior, repeated inconsistencies.
- Present source, uncertainty, context, and careful next steps. Where a discussion-priority category is used, explain it in text and never use color alone. Do not label a person dangerous, guilty, abusive, or unfit based on a mismatch, allegation, or model inference.
- Ask MS Trust is a confidential helper explaining missing information, possible documents, questions to ask, details to verify, and when qualified professional/legal assistance could help.
- Distinguish verified facts, user-provided statements, public-record limitations, and suggestions. Use controlled, supported answers. Never invent evidence or legal conclusions.

### Journey dashboard and post-marriage

- Optional, configurable shared milestones: Matched; Trust Check; Know Each Other; Important Conversations; Family Introduction; Marriage Readiness; Engagement; Wedding; First 100 Days; First Year; Long-term Wellbeing.
- Require mutual consent for shared progress. Milestones are optional, adaptable, and never a competition.
- First 100 Days: days 1–7 expectations; days 8–30 communication; days 31–60 money/family; days 61–90 lifestyle; days 91–100 relationship-health check.
- Each partner may answer independently. Identify differences as discussion prompts, not diagnosis or proof of failure.
- Optional anniversary health reflection: communication, emotional connection, financial stress, family, physical wellbeing, spiritual connection, time together, future goals.
- Suggest optional counselling, couple experiences/retreats, Pratha, wellness, or qualified expert sessions only when real and appropriate. Keep results private and non-diagnostic.

## Acceptance criteria

Partners understand what is private/shared before answering; one partner cannot see another's private responses; both consent to couple mode and shared milestones; AI wording is bounded and nonjudgmental; disagreements are framed constructively; each program can be skipped or exited. Include loading, empty, error, unauthorized, and data-retention states. Validate access controls and tests actually run.
